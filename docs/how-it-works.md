# しくみと精度

QuakeScope の中心は、端末に依存しない C++17 の判定エンジン（`core/src`）です。同じソースを、ESP32 のファームウェアと、ブラウザー版（WebAssembly）の両方で使っています。

```
加速度センサー（100 Hz）
   │  3 方向の加速度（重力を含む）
   ▼
校正 ── 最初の 3 秒で重力の向きを測り、引く（どの向きに置いても動く）
   │
   ├─▶ 震度のフィルター（IIR 2 次 × 5 段）──▶ いまの震度（5 秒の窓）・この揺れの最大
   │
   ├─▶ 1〜10 Hz の帯域 ──▶ STA/LTA（揺れ始め）・一瞬の衝撃の除去
   │
   └─▶ 平常時の震度（雑音の床）
            │
            ▼
      揺れの始まり・レベル（検知／注意／警報）・終わり ──▶ 画面・LED・音・通知・記録
```

## 震度相当の計算

気象庁の[計測震度の算出方法](https://www.jma.go.jp/jma/kishou/know/jishin/kyoshin/kaisetsu/calc_sindo.html)は、次のとおりです。

1. 3 方向の加速度をフーリエ変換し、周期の効果・高い周波数を落とす・低い周波数を落とす、の 3 つのフィルターをかけて戻す。
2. 3 方向を合わせた大きさ（ベクトルの長さ）が、合計 0.3 秒以上になる値 *a* を求める。
3. *I* = 2 log₁₀ *a* + 0.94。小数第 3 位を四捨五入し、小数第 2 位を切り捨てる。

この計算は記録が終わってからでないとできないため、本体では次のように近似しています。

- **フィルター**: 気象庁のフィルターの周波数特性を、100 Hz で動く 2 次の IIR フィルター 5 段（`core/src/jma_filter_coeffs.h`）に合わせました。合わせ方は `tools/fit_jma_digital.py` にあります。0.3〜12 Hz で、気象庁の式との差は最大 0.55 dB です。
- **0.3 秒の値**: 100 Hz では 0.3 秒は 30 サンプルなので、「揺れている間のフィルター後の大きさのうち、大きい方から 30 番目」を求めればよい。これを 30 個だけ持つ最小ヒープで、揺れの間ずっと更新します（メモリーは一定）。
- **いまの震度**は、直近 5 秒の窓で同じ計算をしたものです。

確かめ方:

- `core/src/intensity.cpp` の `computeJmaIntensity` は、気象庁の手順どおりに周波数領域で計算します。これを numpy で別に書いた計算（`core/tools/check_exact.py`）と比べ、差は 10⁻⁶ 以下でした。
- 見本の地震（近い・遠い、計測震度 1〜6、種を変えて 96 本）で、本体の近似と周波数領域の計算の差は**平均 0.024・最大 0.072** です（`core/tests`）。震度の階級は 1.0 刻みなので、階級が変わるのは境目のごく近くだけです。

## 揺れ始めと、誤報の防ぎ方

| しくみ | 中身 | ねらい |
|---|---|---|
| STA/LTA | 1〜10 Hz の帯域で、直近 0.5 秒と 10 秒の平均の強さの比が 3 を超えたら候補 | 小さな P 波でも、ふだんとの違いでとらえる |
| 揺れが続いたか | 直近 1 秒のうち 0.3 秒以上、「直近の最大の 1/4」と「雑音の 2 倍」の両方を超えていたか | ドア・足音のような一瞬の衝撃を除く |
| 雑音の床 | 揺れていないときの震度を追いかける（下がるのは速く・上がるのは 60 秒かけて） | 雑音の多いセンサーでも、雑音で鳴らない |
| 揺れの始まり | 上の 2 つに加えて、震度が「雑音の床 + 0.6」以上 | |
| 終わり | 震度が「雑音の床 + 0.3」を下回り、STA/LTA も落ち着いた状態が 8 秒続いたら | |

見本の揺れでの結果（`core/tests`・ブラウザー版の「しくみと精度」で同じものを確かめられます）:

- 震度 3 以上の近い地震で、強い揺れ（S 波）が来る**前の P 波の段階**で揺れ始めをとらえる（P 波から 1.5 秒以内）。
- ドアを閉めた衝撃・足音（各 6 通り）では、揺れとみなさない。トラックの振動では「検知」まではしても、注意・警報にはならない。
- 警戒レベル: 計測震度 1.5〜2.2 は「検知」まで、2.8〜4.0 は「注意」、4.8〜6.2 は「警報」になる。

## センサーの雑音について

MPU6050 の雑音は、データシートで 400 µg/√Hz です。100 Hz で読むと 1 方向あたり約 3 gal になり、そのまま震度の計算に入れると、**置いておくだけで計測震度 1.5 ほど**になります。最初の版はこれを考えておらず、雑音だけで「揺れの始まり」と判定したり、「揺れが終わらない」状態になったりすることが、雑音を入れた見本で分かりました。

そこで「雑音の床」を測り、それより十分大きい揺れだけを扱うようにしました。雑音 3 gal の見本で:

| 見本 | 結果 |
|---|---|
| 揺れなし 5 分（3 通り） | 揺れとみなさない |
| ドア・足音・トラック（各 3 通り） | 注意・警報にならない |
| 近い地震 震度 3 相当・4.5 相当（各 3 通り） | とらえて注意以上になり、終わりも分かる。震度の差は 0.25 以内 |

その代わり、**震度 2 相当以下の小さな揺れは見逃すことがあります**。もっと小さな揺れまで測りたいときは、雑音の小さいセンサー（例: ADXL355、25 µg/√Hz）に替えるのが根本的な対策です（現在の版は MPU6050 のみ対応）。

## 気象庁の震度との違い

- 気象庁の震度計は、地面や低い建物の 1 階に、しっかり固定して置かれています。本機を高い階やたなの上に置くと、建物やたなの揺れが加わって、**大きく出ることがあります**。
- 本機の値は、本機を置いた 1 点の揺れです。同じ建物の中でも、場所によって変わります。
- 本機は、自分が測った揺れを表示・通知するだけです。ほかの場所の揺れや、これから来る揺れを予想しません。

## 本体のソフトウェアの構成

| 部分 | 動く場所 | 中身 |
|---|---|---|
| センサーの読み取り | コア 1・優先度 10・20 ms ごと | MPU6050 の FIFO から 100 Hz のサンプルを読み、エンジンと波形の記録に渡す |
| 判定エンジン | 同じ | 上のとおり。出来事（揺れ始め・レベル・終わり・センサー異常）をキューに入れる |
| 画面・LED・音・ボタン | メインのループ | 0.1 秒ごとに画面を更新 |
| 通知 | コア 0・別のタスク | HTTPS（LINE・Telegram・Discord）と SMTP。失敗したら 3 回まで送り直す |
| 記録 | メインのループ | LittleFS に要約（JSON）と波形（50 Hz、int16）。容量が減ったら古いものから消す |
| 設定の画面 | メインのループ | WebServer。設定は NVS に保存。秘密の値は画面に返さない |
